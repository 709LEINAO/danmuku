# 斗鱼弹幕台
斗鱼弹幕台是一个自托管的斗鱼直播间弹幕聚合工具，支持多房间共用上游连接、礼物/关注/给分/追踪/教练五个视图，带登录保护，可局域网或公网部署。

当前部署的服务器只是临时的，因为团播我看不会超过一个月所以临时整了一个，没有放在我的那几个主力VPS上，所以我未申请域名和证书，如果你们没有长期稳定的VPS我可以帮你们部署并完成这些。

这里我会记录得比较详细。后续有任何问题随时联系；咱们这面后续需要加功能以支持活动的话（比如选人台一类）也可以直接提。
## 启动与房间列表

启动只监听网页，不自动连接任何房间。 打开某个房间时才建立该房间的弹幕连接，最后一个观看者离开 60 秒后回收。一台服务可同时保留多个房间，多个浏览器页面看同一个房间共用一条上游连接。

房间清单保存在浏览器的 `douyu-danmaku.rooms.v1`，首次打开预置 231059 与 63136。首页右上角 ＋ 按房间号或斗鱼链接添加（添加时即解析短号并记下主播名），行尾 ⋯ 改备注或移除。清单属于当前浏览器和 origin，不在服务端保存，也不随设备同步。

`-room` 仅为兼容旧命令行与旧配置文件保留，解析后不再使用，也不再触发启动即连接；`start.cmd`／`start.sh` 传入的房间参数同样不起作用。连接上限可调：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `-addr` | `0.0.0.0:8787` | 网页监听地址，默认允许同局域网访问 |
| `-max-rooms` | 12 | 同时保留的房间连接上限 |
| `-max-viewers` | 20 | 同时观看及等待解析的网页连接上限 |
| `-room-idle-grace` | `60s` | 最后一个观看者离开后的保留时长，`0` 表示立即回收 |
| `-max-dials` | 2 | 同时进行新建或重连握手的上限 |

上限填 0 或负值（保留时长填负值）会在启动时报错退出。

### Windows

双击 `start.cmd`，或执行：

```bat
start.cmd
douyu-danmaku.exe -addr 0.0.0.0:8787
douyu-danmaku.exe -addr 127.0.0.1:8788 -max-rooms 4 -room-idle-grace 0
```

`start.cmd` 默认监听 `0.0.0.0:8787`，也支持 `DANMAKU_ADDR`。房间在网页的「我的房间」里打开，命令行不再需要指定。

本机打开 [127.0.0.1:8787](http://127.0.0.1:8787/)。其他设备使用服务电脑实际的局域网地址；`127.0.0.1` 表示打开页面的设备自身。局域网地址以启动输出及“房间信息与手机访问”中显示的为准，网卡地址变化后同样看那里。

执行 `build.cmd` 用 PATH 上的 `go` 重建 EXE，构建前须设置 `DANMAKU_PASSWORD`（见「网页访问密码」）。覆盖 EXE 或再次占用同一端口前，需要停止原实例；控制台启动时按 Ctrl+C 退出。

### Linux amd64

将 `douyu-danmaku-linux-amd64` 放到 Linux x86-64 主机后执行：

```sh
chmod +x douyu-danmaku-linux-amd64
./douyu-danmaku-linux-amd64 -addr 0.0.0.0:8787
./douyu-danmaku-linux-amd64 -addr 0.0.0.0:8787 -max-viewers 40
```

也可把 `start.sh` 放在同目录，执行 `sh start.sh`。改变端口的示例：

```sh
DANMAKU_ADDR=0.0.0.0:8788 sh start.sh
```

在源码目录执行 `DANMAKU_PASSWORD=… sh build-linux.sh`，使用符合 `go.mod` 要求的 Go，以 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64` 构建。页面和接口使用同源路径，没有写死客户端 IP 或 Windows 路径。带登录保护的 Linux 版本已部署并通过公网运行验收；部署配置、服务路径与维护命令见 [DEPLOYMENT.md]。

### 房间解析与接口

支持房间号与斗鱼房间链接，也处理短号对应的真实房间。
添加房间时通过 `POST /api/resolve` 解析并保存真实房间号；连续重复提交同一个正在解析的房间不会重新取消该请求。

解析结果在服务端缓存 5 分钟（按归一化后的输入建键，`/api/resolve` 与 `/events` 共用一张表，上限 64 条、满了整表清空，只缓存成功）。第一顺位的解析要抓一整张 m.douyu.com 的 SSR 页面，而重连进一个已经存在的房间时，新解析出来的资料除了拿去查表之外会被整个丢弃——手机息屏反复重连时这趟回源是纯白做的。缓存只影响「多久之后才重新去问斗鱼」，不改变任何解析规则。

`GET /api/status?rid=` 与 `GET /events?room=` 都要求房间参数，缺参数返回 400，返回体统一包在 `{"roomId","generation","data"}` 信封里。`/api/status` 是只读的：没有任何页面订阅该房间时返回 404 `room_inactive`，只有 `/events?room=` 才会建立房间。`GET /api/access` 返回本机与局域网可用地址。

`GET`／`POST /api/settings` 仍在服务端保留 `defaultRoom` 字段，写入可执行文件旁的 `douyu-danmaku.settings.json`，但页面已不再调用，该值只会喂给同样不再使用的 `-room`；它属于兼容遗留，不影响任何行为。

## 网页访问密码

密码有两个来源：构建时 `build.cmd`／`build-linux.sh` 读取环境变量 `DANMAKU_PASSWORD`，经 `-ldflags -X` 注入二进制，未设置则拒绝构建——分发出去的程序因此开箱即用；运行时同名环境变量非空则覆盖注入值。两者皆空程序拒绝启动，不能用空值关闭登录。口令避免包含引号，否则构建脚本的参数会被截断。不要把密码填入 `-room`、地址参数、前端代码或默认房间 JSON。

运行时覆盖：Windows 可在启动程序前为当前进程环境设置 `DANMAKU_PASSWORD`；Linux 可使用 shell 的受限环境文件或 systemd 的 `EnvironmentFile`。例如在仅服务管理员可读的 `/etc/douyu-danmaku.env` 中写入 `DANMAKU_PASSWORD=自行设置的访问密码`，将文件权限设为 `600`，然后在服务单元 `[Service]` 中配置 `EnvironmentFile=/etc/douyu-danmaku.env` 并重启服务。环境变量只在进程启动时读取；更换密码后重启即撤销全部原有登录。命令行参数不提供密码选项。

登录成功后，会话在服务端内存保存 24 小时，不随使用延长；关闭／重启程序或退出登录使相应会话失效，无认证数据库或认证文件需要备份。随机会话凭据只放在 `HttpOnly`、`SameSite=Lax`、当前主机 `/` 路径的 cookie 中，不进入 URL 或浏览器本地存储。HTTP IP 地址可正常登录；服务直接处理 TLS 时 cookie 自动标记 `Secure`。服务不信任 `X-Forwarded-*` 来判断 HTTPS 或客户端 IP；当前直接 HTTP 部署无需代理配置。

设置中点击“退出登录”可撤销当前会话，保留本浏览器的主题、字号、关注等偏好。到期或退出时，已连接的 SSE 也会结束授权并让页面返回登录。登录失败按实际连接 IP 计数，1 分钟内最多允许 5 次错误尝试，之后返回 429 与 `Retry-After`；过期计数自动清除，IP 表及会话表均有固定上限。

接口验证约定：

- `GET /login`：公开的中文登录表单；`POST /login` 使用 `application/x-www-form-urlencoded`，字段为 `password` 和可选的站内 `next`。正确时返回 303 并设置 cookie；错误返回 401，非法跨源请求返回 403。
- `POST /logout`：携带会话 cookie 及与当前服务一致的 `Origin`（或同源 `Referer`），成功撤销会话并 303 返回 `/login`。退出操作不使用 GET。
- 根页面、所有 `/api/*`（含房间解析、访问地址、遗留的默认房间配置、追踪页的查分代理与徽章图标清单）、`GET /events` 及徽章图标的 `/assets/*` 均要求登录。未登录访问根页面会跳转登录，接口与 SSE 返回 JSON 401，不返回消息历史或设置。`/api/events` 不是实际 SSE 路由，未登录同样被拦截。
- 所有带 cookie 的状态修改请求要求同源 `Origin` 或 `Referer`；浏览器正常表单／fetch 自动携带，脚本客户端需明确设置与 URL 相同的 `Origin` 并保存 cookie。无跨源接口或公开例外；登录与受保护页面／接口均使用 `Cache-Control: no-store`。
- 登录只控制网页访问，`/api/settings` 仍只有 `defaultRoom` 字段；密码、会话和失败计数不会出现在设置／状态响应或应用日志中。

## 显示方式：手机端与平板端

登录页密码框下面有一组「显示方式」，选完再登录；之后在设置面板的同名分组里随时能改。两种模式都保存在浏览器的 `douyu-danmaku.settings.v3` 里，跟主题、字号共用一份。

登录页会先猜一个默认值：`iPad` UA、报成 macOS 但有多点触控的 iPadOS、非 Mobile 的 Android，以及屏幕短边 ≥ 600 px 的设备都默认平板端，其余默认手机端。这只是默认值——iPadOS 桌面模式自报 macOS，宽度与指针探测都不可靠，所以最终以用户选的为准，布局完全由 `:root[data-layout]` 驱动，不跟视口宽度绑定。

- 手机端：原来的单屏布局，房间列表与监看界面互斥，返回键在左上角。行为与之前完全一致。
- 平板端：左边 280 px 常驻房间列表，右边监看界面。列表是留白隔开的圆角卡片——手机上那种整幅分隔线放进 280 px 的窄栏会把没几行的列表切得很碎；正在看的房间整块上底色、描一圈细边，左侧一枚居中的红色圆头竖条，配合红色标题指同一件事。「⋯」编辑按钮常驻不做悬停才显形（平板是触屏，`:hover` 在那上面不成立）。左上角按钮收起／展开左栏（收起状态也会保存）。没选房间时右侧显示空状态。左栏常驻后右栏顶栏不再重复放设置入口。视口被分屏挤到 700 px 以下时自动回落成单栏互斥，返回键重新出现。

平板端默认打开「斗鱼原生还原」（设置面板里可单独关掉，关掉后只剩分栏）。还原的部分取自斗鱼网页端直播间的样式实测：

- 弹幕改成斗鱼那种流式排版——徽章、昵称、冒号、正文顺着排，不再用手机端那列 5em 定宽对齐。昵称完整显示，只在长过整行时才裁（手机端仍是定宽列加省略号）。
- 贵族、用户等级、粉丝牌、房管／超管四类徽章，档位边界照抄斗鱼配置：粉丝牌每 5 级一档（0 级为灰牌），用户等级 lv1–14 同档、之后每 10 级一档。
- 彩色弹幕按协议 `col` 字段上色，颜色取自斗鱼的 `Barrage-content--color0…5`：`#ff314e`／`#4a94ef`／`#70c150`／`#d4a113`／`#8a5be9`／`#e04ac0`；缺失或越界回落默认正文色。
- 贵族整行加底色：浅色主题用斗鱼的米黄底深字，深色主题改成透金薄底加左侧描边（斗鱼那套分级底色属于进场提醒，直接用在深色聊天行上太刺眼）。
- 礼物行正文用斗鱼橙 `#ff5d23`。
- 徽章条按中线对齐昵称而不是基线。徽章只有 0.72 em，基线对齐会把整条压到文字下方（实测低 2.5 px，贵族徽章最显眼）。
- 昵称显式声明 `align-self:baseline`，否则整行后半截会掉下去。 身份区 `.identity` 是 `align-items:center` 的 `inline-flex`：一旦没有任何一项参与基线对齐，浏览器只能拿「第一个 flex 项」——也就是徽章条——凑出这个盒子对外的基线，而徽章条越高基线掉得越狠。普通弹幕打头的是 0.72 em 的等级徽章，差 0.62 px 看不出来；贵宾进场提示打头的是 1.6 em 的贵族图标，后面那句「伯爵 来了」就整整掉了 3.73 px。把昵称单独标成基线来源之后，徽章仍按 `center` 摆（徽章条与昵称中线仍差 0.17 px），而行尾文字与昵称落在同一条基线上——实测值与「昵称和正文直接做兄弟节点」的对照组完全一致。

房管与特别关注发言的边框底纹只包住文字本身，一句「短」不再拉成横贯整屏的一条：底色与描边挪到内层 `.message-line` 上，宽度 `fit-content`、上限 `100%`，长句照常换行填满。外层 `<article>` 仍占满整行，所以右侧的「⋯」按钮还是对齐在同一列。礼物行、给分行、进场提示行也会带 `is-admin`／`is-followed`，它们各有自己的底色，这条规则一律不碰。

手机端不受任何影响：徽章 DOM 照建但整条 `display:none`，不占宽度，也不会为看不见的图去连一次网。进场提醒见下文「贵宾进场提示」。

### 原生徽章图标（服务端代理 + 缓存 + 定时换新）

平板原生模式下，用户等级、贵族、粉丝牌三种徽章用的是斗鱼自己的图，但浏览器一次也不连斗鱼：Go 端按需回源、缓存在内存里、定时 revalidate，页面只连本机。

- `GET /api/icons` 报出可用档位（`ready`、`levelMax`、`medalMax`、`noble[]`）。说 not ready 就一张图都不请求，徽章保持下面那套 CSS 自绘。
- `GET /assets/level/{light|dark}/{1..151}` —— `userLevelIconV6/web-{主题}/newm3_lv{N}.png`，图里已经画好数字，所以整块让位给图。lv151 是逐个试出来的上限，152 起上游 404。换主题会换成另一套。
- `GET /assets/noble/{1..9}` —— 取自 `wconf.douyucdn.cn/resource/noble/global/web.json` 的 `host + web_symbol_pic1`，28×28，皇帝／超级皇帝／幻神是 GIF。
- `GET /assets/medal/{0..60}` —— 取自 `fans_medal_web_v5.json` 的 `commBg["bg_N"]` → `bgPics`，每 5 级一档、顶格封在 60 级。斗鱼另有一版 84 px 宽的 `lbg_`，宽出来的 18 px 是留给牌尾挂件的，我们不画挂件所以取 66 px 窄版。
- `GET /assets/medal/room/{roomID}` —— 该房间限时活动的牌前缀（`fansMedals` 里房间号明确列出的那 43 条，覆盖 107 个房间）。`room_ids_v2` 写成 `{"0":1}` 的 385 条不是房间默认样式，一律不收。绝大多数房间没有前缀，404 允许浏览器缓存十分钟。
- `GET /assets/medal/room/{roomID}/{挂件ID}` —— 同一个位置还有一种按人发的牌前缀。弹幕里的 `nail` 字段是「挂件ID\_房间号」用 `/` 串起来的一串，取房间号对得上这块粉丝牌的那条（斗鱼前端的 `filterValidAttrId` 就是这么筛的），ID 查 `webconf.douyucdn.cn/resource/common/property_info_22.json` 的 `data.property_info[ID].web_pic`。个人挂件盖过房间那张；挂件段是 0、查不到、或干脆长歪，都只是退回房间的限时前缀，不会让整条 404。63136 现场 216 个带前缀的粉丝牌里，143 个走房间默认、73 个有自己的挂件。

这个代理认键不认地址：路径里能出现的只有主题名和一个整数，真实 URL 由服务端查斗鱼配置得出，再过一遍主机白名单（`shark2`／`sta-op`／`res.douyucdn.cn`）。任何时候都塞不进一个外部地址，所以它不会变成开放代理；它和其余接口一样挡在登录后面。

缓存 24 MiB 封顶、LRU 淘汰，同一张图的并发首次请求合并成一次回源。默认 12 小时刷新一轮：先换配置表，再用 `If-None-Match`／`If-Modified-Since` 把已缓存的图挨个问一遍——304 保留旧图，200 换上新图并换 ETag。任何一步失败都保留旧数据（单边失败保留旧的那一半，整轮失败保留整份上一版），上游挂掉时已缓存的照常供图。

粉丝牌的牌名和等级数字仍由我们画（斗鱼用的是 base64 数字精灵图），位置按实测的 shadow DOM 比例摆：底图 66×16、牌名从 x=22 起并 `scale(.9)`。等级数字分两种摆法，跟着牌前缀走：

- 没有牌前缀：数字 18×16 占满左端 (1,0)，就是常见的那种「数字＋牌名」两色牌。
- 有牌前缀：前缀金章 22×22 压在左端，数字缩成 10 px 高、贴着底图下沿，坐在金章下沿。压在金章正中间会被花纹吃掉第一位数。数字再补一圈描边——斗鱼的精灵图自带描边，纯文字不描就糊。描边用四个 1 px 硬偏移而不是 `blur`：`blur` 的黑晕会糊出去两个像素，正好盖在牌名第一个字的左边，看上去就像「冬」被啃了一口。
- 金章高 22、底图高 16，多出来的 6 px 上下各分 3。原生是全部向上探（下沿与底图齐平），那样这块牌的视觉重心会比同一行的等级徽章和昵称高出 2.4 px；斗鱼的弹幕行行距松看不太出来，我们的行是紧排的，一眼就是「徽章没跟文字对齐」。改成居中之后，整条徽章带与昵称字形的中线差 0.17 px。

这里有一处故意不照抄原生：原生金章占 1..23、数字格 13..26、牌名从 22 起，三者互相压着。斗鱼那张 28×22 的精灵图是斜体、`contain` 收进 13×10 之后两边还留白，所以挤得进牌名底下；我们的方头文字挤不进去，照抄会让「冬」直接盖掉第二位数。改成数字收进 13..25、牌名整体右移到 28 起，让出一条真的缝，右边少留点内边距把牌名宽度补回来。实测现场 277 块牌，数字与牌名之间最窄的一处还有 2.73 px 富余，无一块牌名被截断。

图没解码完之前，预备态是 1 px 透明片而不是 `display:none`：`display:none` 的图浏览器压根不会去取，于是永远等不到 `load`、永远换不上原生图。同理这些 `<img>` 不加 `loading=lazy`。取不到图（404／502／配置没回来／局域网离线）时自动退回 CSS 自绘徽章，位置不会变成一排碎图。

## 我的房间与五个页面

首页「我的房间」只做一件事：列出保存的房间，点进去开始接收。返回列表会断开本页连接并清空本页消息，保留房间清单、关注与显示设置。

- 全部：礼物置顶 → 特别关注发言 → 普通聊天。礼物与关注区为空时不预留高度。每位送礼用户一行，行内用独立胶囊展示不同礼物；关注用户最多五行。普通聊天采用“昵称：内容”。
- 礼物：保留当前房间最近 500 条礼物原始事件，按每条事件的真实人民币参考总价降序，同价新消息优先；免费道具、孵化产物、鱼丸与未知参考价一并单列在分隔线之下。数量、连击、时间及原始资料可查看详情。自定义展示档位不会改变此页价格或排序。
- 给分：独立收集最近 500 条匹配的原始弹幕，按原始接收时间排列，同时间顺序稳定。识别完整的 `#给目标 整数` 与 `#炸目标 整数`，支持空白与全角规范化，仅匹配消息正文开头的有效指令，保留原文详情；带昵称或 UID 前缀的引用转发只留在全部页，不触发给分红点。发送者沿用原始事件身份；不同原始事件即使指令相同也分别保留，每条消息仅记一次，只收集、不执行任何指令。新到记录显示红点，打开页面后清除；重放不重复收集或提醒。
- 追踪：盯住若干主播的查分余额与今日流水，与弹幕流无关。详见下节。
- 弹幕教练：在设定时段内，聚合弹幕达到门槛就震一下；同页管理屏幕常亮与最近提醒记录。详见下节。

顶部房间按钮可暂停接收、重新连接或查看手机访问地址，左上角返回房间列表；设置中管理关注、主题、字号、展示开关、时长和礼物规则。界面不展示语音醒目留言、SC、粉丝牌或等级。

## 追踪页

追踪页读团播查分站的公开主播名册，用来看某几位主播的余额变化，不涉及弹幕连接，也不发送任何指令。

前端不直连第三方站（对方没有 CORS 头），一律经 `GET /api/scoreboard/anchors` 代理。代理只转出用得上的字段（斗鱼 UID、名字、给分简称、房间号、开播状态、余额、今日流水、是否允许给分／炸分），34 KB 的上游响应压到约 4 KB，并在服务端缓存 45 秒；响应体上限 4 MB。这个接口和其他 `/api/*` 一样要求登录。

页面只在追踪页可见且房间页处于前台时轮询，间隔 60 秒，「刷新」按钮可立即拉一次；离开页面或退回房间列表即停止。上游约 60 秒才换一次数，`updatedAt` 未变化时判定为同一份数据，增量保持原样，避免刚出现的 `+200` 被一次空刷新抹成「无变化」。追踪名单存在 `douyu-danmaku.track.v1`，最多 60 人，属于当前浏览器；名单里的人从上游名册消失时行内显示为「名单里已经没有这个人了」。「添加」可按名字、UID 或给分简称筛选整份名册。

## 弹幕教练页

时段布防：开关加起止时间，结束早于开始表示跨零点（例如 22:00 – 02:00），两个时间填成一样表示全天。默认 20:00 – 23:59，默认关闭。

聚合门槛默认 8 条，范围 5–500，按合并后的总条数算。最短间隔默认 60 秒，范围 1–600。

去重认文案不认分组：同一句话在安静满一个最短间隔之前只提醒一次，这波聚合持续多少秒都一样；只要它还在被聚合就一直续期。不同内容之间也至少隔开这个间隔，被让路的内容只写一条「间隔内跳过」日志，间隔过去后仍会轮到它，不会被永久吞掉。SSE 重连走的是清场 + 重放最近 300 条，不会把同一波刷屏重震一遍；只有换房间或退回列表才清空提醒记录。「最近提醒」保留最近 40 条，标注「已提醒／提醒没发出去／间隔内跳过／连接中断」。

提醒方式按设备能力显示，用不上的开关直接隐藏：

- 震动需要 `navigator.vibrate`。规范要求文档可见才允许震动，所以「屏幕常亮」和震动实际是一套。
- iPhone / iPad 的 Safari 从未实现 Vibration API，网页震不动；火狐 129 起已移除震动实现，安卓版仍保留 `navigator.vibrate` 且返回 `true` 却不震，只能按 UA 排除。这两类设备改为显示提示音开关（880 Hz 短提示，需先点一次「试一下」解锁音频）。能震的设备不提供提示音开关。
- 屏幕常亮用 Screen Wake Lock API，该接口要求安全上下文，当前 HTTP 部署下整块隐藏并给出说明。进入房间即生效，退回列表或切走页面自动释放，回来自动接上；与布防无关。息屏会让系统挂起页面、悄悄掐断 SSE，这是手机上漏消息的主要原因，回到前台时本页立即重连并补齐服务端保留的最近 300 条。

「试一下」按当前开关实际震一下或响一下，用来确认设备真的支持。测试预览的聚合不会触发提醒。

## 设置与展示开关

深色／浅色主题可切换；字号为 12–20 px，每步 0.5 px，默认 14 px。紧凑礼物／管理员消息使用克制的强调背景；关注消息在深色主题中使用暗金背景、红色昵称及浅色正文。轻微入场效果约 700 ms，并尊重系统“减少动态效果”。

设置面板顶部的「显示方式」切换手机端／平板端，平板端下多一个「斗鱼原生还原」开关（默认开）；两者与主题、字号存在同一份设置里，详见上文。

### 贵宾进场提示

主页弹幕流里按时间混排进场提示，文案照抄斗鱼网页端（「伯爵 来了」），中间那截称号单独上色。平板端开启斗鱼原生还原后，进场行套斗鱼自己的底色档位：骑士 `#ece8db`、子爵 `#f7ebe3`、伯爵系（3/4/5/6/8/9）`#deeefb`、游侠 `#e3e6e8`；深色主题下按斗鱼的做法把同一组颜色压到低透明度叠在深底上。提示最多保留最近 60 条，关掉开关是整批隐藏、不丢数据。

只放行伯爵及以上的贵族：斗鱼网页端自己也不给普通观众出进场行（实测该房间 `uenter` 约 4 条／秒，全放行几十秒就能把 300 条历史冲干净）；即便如此仍会扎堆，所以另加令牌桶——突发 5 条、之后每 2 秒 1 条。房管与超管的进场整条丢弃：他们在自己房间里进进出出频繁，播报价值配不上占的位置。骑士(1)、子爵(2) 是最便宜的两档，游侠(7) 是体验档，这三种刷得跟钻粉一样勤，同样不成行；伯爵(3)、公爵(4)、国王(5)、皇帝(6)、超级皇帝(8)、幻神(9) 保留。判定只看贵族档位，所以兼任房管的公爵照常播报成「公爵 来了」。门槛写在服务端 `noticeNoble` 与前端同名常量两处，服务端 `guestEnter` 是第一道闸，前端 `receiveMessage` 再挡一道，避免旧服务端配新页面时又冒出来。`NOBLE_TONE` 底色表照抄斗鱼九档不做裁剪，改回门槛即可直接复用。「关注的人进场」做不到：关注名单只存在浏览器里、从不发给服务端，服务端无从判断该放行谁。

特意没做：

- 钻粉进场实在太多，所以 `guestEnter` 不再把 `diaf=1` 当贵宾，`DiamondFan`（`dfgm` 月数／`adays` 天数）整块解析也一并删掉。
- 房管与超管进场，以及骑士／子爵／游侠三档贵族进场。同理，`guestEnter` 现在只认伯爵及以上（`nl>=3 && nl!=7`），`rg=4`／`pg=5` 与 `nl` 为 1／2／7 都不再单独成行；兼任房管的高档贵族照常按贵族播报。
- 用户升级与粉丝牌升级。`upgrade`／`blab` 两类包在 `normalizeEvent` 里直接落到 `default` 分支丢弃，不再产生事件。
- 进场动画。进场行只做静态渲染，不接淡入或位移。
- 全站广播，也就是「谁谁谁在什么房间掉落宝箱／送出什么礼物」那种横幅。`spbc` 在服务端仍归一成 `kind:"broadcast"` 留作计数，但前端不接收；`anbc`／`rnewbc`（开通、续费贵族）载荷里只有主播昵称、没有房间号，无法归属到当前房间，从头就没实现。

教练页的布防、门槛、间隔、提醒方式与屏幕常亮直接在该页保存，不在设置面板里；其余项目在设置面板。以下九项默认开启并保存到当前浏览器：主页礼物置顶、主页关注置顶、显示贵宾进场提示、礼物强调、关注强调、房管／超管强调、多人同文强调、轻微入场效果、给分红点提醒。关闭对应展示功能仍继续接收、计时和保留角色标记。

| 设置 | 默认值 | 可配置范围 |
| --- | --- | --- |
| 礼物最低参考价 | 100 元 | 100–100000000 元 |
| 礼物最高参考价 | 不限 | 留空或不低于最低价，含端点 |
| 礼物置顶停留 | 100 秒 | 1–86400 秒 |
| 关注发言停留 | 30 秒 | 1–86400 秒 |
| 多人同文不活跃时长 | 10 秒 | 1–86400 秒 |
| 整体字号 | 14 px | 12–20 px，每步 0.5 px |

设置里的“测试效果”进入带测试标记的独立本地预览，可生成普通聊天、关注发言、房管和礼物样例（普通聊天样例会轮流带上等级、粉丝牌、贵族与彩色弹幕，方便在平板端预览原生还原效果），也可生成未知价格的“白金独角兽”以查看规则命中、重复累加与续期。预览不发送到直播间，不更改真实关注名单，也不混入真实记录；实时接收在后台继续。清空、退出或刷新可结束预览。

## 首页礼物与自定义名称规则（这个只是顺手做的，没有太深入）

通常以 `giftReference.currency = YUCHI` 的有效人民币参考总价判断是否落入设置区间。数量来自本条 `gfcnt`，连击来自 `hits`，不把数量乘以连击。

在原有 v2 目录上，补充官方 v5 基础目录 `/api/gift/v5/web/base/list` 与房间明细 `/japi/reward/giftv2/list/details/web/v5`。三者按解析后的真实 RID 并行请求；v5 按官方同 ID 浅覆盖规则合并，`coverage=1` 只覆盖基础目录已有条目，再补进 v2，不因房间礼物选单更小而丢失原有覆盖。缺失字段不当成零，价格与币种来自同一有效记录；v5 参考来源在详情中显示为“斗鱼房间目录 v5”。

第四个来源是全站道具配置 `https://webconf.douyucdn.cn/resource/common/prop_gift_list/prop_gift_config.json`（JSONP，1585 条，按 gfid 建索引）。单价字段 `pc` 与房间目录的 `price` 同单位同值，全库 `ry=0` 即没有鱼丸档。优先级写死在最底层，房间目录永远压过它。这份表由斗鱼按小数下发过 `devote`（1545 礼物buff = 665.9），因此按行解码并向下取整，单独一行长歪不会废掉整表。这份表 1.4 MB 且与房间号无关，因此按进程共享一份、12 小时刷新（与徽章图标的回源间隔同一套约定），不再每开一个房间就重下一遍；三个按 RID 的房间目录接口照旧各房间各打一次。取表的超时相应放宽到 30 秒（1.4 MB 在 5 秒内要求持续 280 KB/s，弱网必挂），三个 RID 接口仍各自维持 5 秒。

同一 UID 的礼物在一行中展示，不同礼物拥有独立胶囊。相同礼物在活跃期内再次达标时累加本条原始数量，例如 200 + 200 = 400，并以这条事件的原始 `at` 重新计算该胶囊的到期时间；该用户的其他礼物不会被一起续期。数量以整数精确累加。重放不重复计数，也不使用重放时刻续期。

礼物区容纳两位用户的行，多余内容可滚动；为空时不占位。置顶到期仅移除主页胶囊，礼物页仍按其 500 条历史上限保留事件。活跃数量累计独立于这 500 条历史，因此历史滚动淘汰不会直接削减仍活跃胶囊的累计数。修改停留时长保留活跃总量；修改价格区间或自定义名称规则时，会从仍保留的最近 500 条礼物重建，并提示这一范围限制。

设置支持编辑“完整礼物名称 → 展示档位”。名称两端空白会清除，之后按完整名称精确匹配。首次没有保存过该偏好时，预置 白金独角兽 → 100；删除所有规则后会保存为空，不会自动重新添加。

匹配规则时，配置档位仅替代首页最低／最高区间的判断值，按每条事件判断，不随数量或连击倍乘。实际礼物参考价、详情和礼物页排序保持原值。它可让已解析出完整名称、但价格未知的礼物参与首页展示。

## 特别关注与相同弹幕

关注按稳定数字 UID 保存，可加备注，名单可以超过五人。只有关注用户实际发言后才出现置顶；不会自动关注送礼用户或管理员。最多展示最近说话的五位不同活跃用户，每人保留最新原始发言，新发言使该用户移至最前并单独续期。默认以最新原始发言时间 + 30 秒到期，可在设置修改。到期后的重复发言重新开始；关注发言同时保留在普通聊天中。取消关注或换房会清除相应房间置顶状态，关注名单仍保存。

文字只做保守的 Unicode 与空白清理，不模糊匹配不同语义或标点；保留原文供详情查看。昵称与正文隔离书写方向，内容按纯文本呈现。
